# Process architecture

Step zero of the lifecycle. Before any process can be modelled, someone has
to say which processes exist, how they relate, and which of them is worth
the effort.

| Module | Topic |
|---|---|
| [bpm-lifecycle](bpm-lifecycle/) | the six phases and what each hands on |
| [process-categories](process-categories/) | Porter: core, support, management |
| [process-relations](process-relations/) | sequence, decomposition, specialisation |
| [process-landscape](process-landscape/) | the level-one map and the APQC framework |
| [process-portfolio](process-portfolio/) | which process to improve first |

The block is where the subject is least like computer science and most like
organisation: nothing here is computed, everything is agreed. What the code
adds is the part that can be checked: a decomposition must not contain a
cycle, a map must be complete for every party, an APQC number must have the
right number of dots.
