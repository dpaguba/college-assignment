# Which tasks automate

Five criteria: rule-based, structured input, high frequency, stable process,
low exception rate.

| Task | Score |
|---|---:|
| move invoices from a mailbox into the ERP | 5 |
| reconcile master data between two systems | 4 |
| compile a monthly report | 4 |
| answer a complaint | 1 |
| decide a credit application | 1 |

## The exception rate decides

A process with five percent exceptions pays. One with thirty percent does not:
almost every third case is handled by hand anyway, the robot still needs
maintenance, and the exception now arrives in a half-processed state, which is
worse than before. The number to ask for is the exception rate, not the case
volume, and the second question is how often the system underneath changes.

## Why judgement does not automate

A rule maps cases to answers. A judgement weighs reasons that contradict each
other, and the result has to hold up to challenge rather than merely be correct.
Encoding it does not automate the judgement; it freezes one particular
judgement, and changing it then needs a developer instead of a conversation.
